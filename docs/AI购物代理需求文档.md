## 1. 背景

买家在高决策商品上要花大量时间查参数、手册和型号，才能决定买什么。购买代理已经能通过 Shopify UCP 查询商品目录，也能通过 Agentic Commerce Protocol（OpenAI、Stripe、Meta）发起结账。2026 年 3 月，ChatGPT 站内即时结账收缩，用户主要用代理做调研，商家希望自己掌握结账和客户关系。国内综合电商对外部购买代理仍然基本封闭。

现有目录的缺口在决策质量：字段缺单位和条件，空值会被模型补全，客服回答散落在聊天里，下一个代理还要再问一遍。

## 2. 产品定义

平台是一个垂直品类的商品事实层，外加给购买代理使用的工具接口。

- 商品以结构化事实保存。每条事实带单位、适用条件、来源、信任等级和版本。
- 必填字段没有值时，接口返回「未知」。未知是合法结果。
- 购买代理通过工具完成搜索、详情、对比和提问。网页供卖家录入、买家抽查短名单。
- 客服回答在卖家确认、且与已有事实不冲突后，晋升为规格。之后的代理直接读取这条规格。
- 结账和客户关系留在卖家侧。平台对可归因的成交抽取佣金。

买家是委托方。代理可以完成调研；只有在买家事先写下的授权范围内，后期才允许自动下单。

## 3. 目标与非目标

### 3.1 目标

1. 把一类商品的选型从「人工翻手册」变成「代理给出带来源的短名单」。
2. 让卖家用确认抽取结果的方式补齐事实，而不是手填长表。
3. 把重复的客服问题合并、提纯，并写回商品事实。
4. 为后续的归因佣金留下可核对的订单关联，首期不自建支付。

### 3.2 非目标（首期不做）

- 通用多品类商城、自建物流、自建支付、站内广告。
- 无额度、无撤销窗口的自动扣款。
- 爬取淘宝、京东、拼多多页面。
- 把营销文案、未确认聊天记录写成可筛选规格。
- 出售完整度分数，或允许付费进入不符合硬性约束的短名单。

## 4. 角色

| 角色 | 诉求 |
| --- | --- |
| 买家 | 用自然语言给出约束，得到可核对的短名单，并自己完成付款 |
| 购买代理 | 稳定地搜索、对比、发现未知项，并在缺口处提出可复用的问题 |
| 卖家 | 一次确认规格，减少重复咨询，并获得与约束匹配的订单 |
| 卖家助手 | 只依据已确认事实起草回答，答不了就交给人 |
| 平台运营 | 维护类目模板，处理事实冲突和滥用提问 |

首期更早的付费方可以是买家（按席位使用采购代理）。卖家入驻、上架、被查询、被提问都不收费。

## 5. 首期品类

首期只开放一个品类。品类需同时满足：

- 买不买主要由参数、兼容和安装条件决定。
- 同一类问题会反复出现在客服对话里。
- 卖家手里已有规格书或手册，适合抽取后确认。

候选：装机配件的接口与功率兼容、工业易损件的替换型号、大家电的尺寸与安装条件。服饰、食品和低价标品不进入首期。具体品类在评审时确认，见第 12 节。

## 6. 商业规则

这些规则约束功能，避免排序和收费互相打架。

| 规则 | 要求 |
| --- | --- |
| 入驻与查询 | 免费。提问也免费 |
| 主收入 | 仅对可归因成交抽佣。设计区间 3%–8%，低于综合电商，因为平台不包物流、不拿走客户关系。具体比例按品类在上线前确认 |
| 退货 | 退货成功则退回该笔佣金 |
| 订阅 | 第二阶段。购买提问工作台、SKU 额度、多渠道同步。免费档可限制 SKU 数和席位，不可限制「符合约束的商品被如实返回」 |
| 资料整理 | 可选项目制，按规格书抽取并提交卖家确认。它是实施服务，不替代佣金 |
| 广告与完整度 | 首期无广告。完整度只由字段、来源和新鲜度计算，不可购买 |
| 排序 | 先过滤硬性约束，再按事实完整度、价格、库存排序。付费不能把不满足约束的商品送进短名单 |

冷启动阶段可以没有成交佣金，只需把归因所需的点击和订单关联记下来。

## 7. 概念与信任等级

### 7.1 对象

| 对象 | 含义 |
| --- | --- |
| 类目模板 | 该品类的属性定义：名称、类型、单位、是否必填、允许的条件 |
| 事实 | 一个属性在特定条件下的取值，带来源和信任等级 |
| 规格书 | 卖家上传的原文，作为证据，供检索和抽查 |
| 问题簇 | 对同一商品、同一属性、同一使用条件的合并提问 |
| 候选事实 | 从规格书或回答中抽出、尚未确认的值 |
| 短名单 | 代理给出的候选商品，每条硬性结论都能指回事实 |
| 归因 | 短名单交给买家之后，在窗口期内产生的可关联订单 |

### 7.2 信任等级

| 等级 | 来源 | 能否参与硬性筛选 | 能否覆盖已有规格 |
| --- | --- | --- | --- |
| 规格 | 厂商规格书、检测认证，且卖家已确认抽取结果 | 能 | 能，保留旧版本 |
| 确认参数 | 卖家在模板中直接确认 | 能 | 能，保留确认人和时间 |
| 晋升事实 | 客服回答经卖家确认，且与已有事实不冲突 | 能 | 能，必须附带原问题 |
| 未确认问答 | 助手或人工刚刚给出的回答 | 不能 | 不能，只能引用 |
| 冲突 | 两个已存在来源不一致 | 不能单独采信 | 不能。两份都展示，等待卖家裁定 |
| 未知 | 必填或被问到的字段没有值 | 不能当成任意值 | 不适用 |

营销句（无来源的主观描述）可以展示，不能写入可筛选规格。

## 8. 主流程

### 8.1 卖家补齐事实

1. 卖家创建商品，选择类目模板。
2. 上传规格书、手册或尺寸图。
3. 系统抽出候选事实，标出单位、条件和原文位置。
4. 卖家逐条确认、改正或标为未知。
5. 系统计算完整度。未知项保留为未知。
6. 商品对购买代理可查询。

### 8.2 代理选型

1. 买家用自然语言描述需求。代理把需求写成约束：预算、尺寸、接口、功率、认证、是否可退等。
2. 代理调用搜索。不满足硬性约束的商品不进入结果。
3. 代理对候选调用详情或对比。空字段返回未知。
4. 代理生成短名单。每条用于筛选的结论附带事实标识和来源。
5. 买家在短名单页抽查证据，并通过卖家收银台付款。平台记录归因事件。

### 8.3 提问并晋升

1. 代理发现决策所需字段为未知，发起结构化提问。
2. 系统先并入已有问题簇。已有已晋升答案则直接返回，不再通知卖家。
3. 没有答案时，卖家助手只依据已确认事实起草。起草不了则进入人工问题箱。
4. 回答被抽成候选事实。卖家确认且不冲突，才晋升为规格。
5. 之后任何代理读取该规格。

## 9. 功能需求

优先级：P0 为首期必须，P1 为首期之后的第一批，P2 为授权购买阶段。

### 9.1 类目模板（P0）

系统提供一套首期品类模板。

- 每个属性包含：标识、名称、数据类型、单位、是否必填、条件说明、示例。
- 模板区分三类信息：测量值、否定信息（不含、不兼容）、安装或使用约束。
- 运营可以增改属性。已有事实保留，不因模板调整被静默删除。
- 卖家不能自行发明可筛选字段。模板外的说明进入备注或原文，不参与硬性筛选。

验收：

- 给定一个缺少必填属性的商品，详情接口对该属性返回未知，而不是省略字段或返回空字符串冒充有值。
- 否定信息可以被搜索约束命中，例如「不兼容 PD 3.1」会使「必须支持 PD 3.1」的搜索排除该商品。

### 9.2 商品与事实（P0）

- 商品包含标识、卖家、类目、标题、在售状态、价格、库存、可退政策、可售状态和可售日期。
- 可售状态为现货、缺货、预售或延期交货。预售和延期交货必须带可售日期。
- 事实包含：属性、值、单位、条件、信任等级、来源、确认人、确认时间、版本。安全认证另带机构、编号和文件地址。
- 型号和 GTIN 是身份事实。未确认时返回未知。标题中的数字不能当作型号或 GTIN。
- 更新事实生成新版本，旧版本可追溯。
- 价格和库存与规格事实分开。接口返回价格更新时间和库存更新时间。价格过期不影响规格版本，但影响是否可被推荐，并在搜索响应中说明原因。
- 冲突发生时，新旧两份事实都保留为冲突状态，商品在该属性上不可被硬性筛选采信，直到卖家裁定。

验收：

- 任一硬性结论可以沿事实标识打开来源和版本。
- 规格书与聊天记录冲突时，对比结果同时展示双方，并标明不可采信。

### 9.3 规格书抽取与确认（P0）

- 卖家上传 PDF 或图片。系统保存原文，并抽取候选事实。
- 每条候选事实指向原文位置。卖家可以确认、修改、驳回或标为未知。
- 未经确认的候选事实不可被搜索和对比当作规格。
- 抽取失败时，商品仍可创建，缺失字段保持未知。

验收：

- 卖家未确认前，代理详情中看不到这些候选值。
- 确认后，事实来源为「规格」，并带原文位置。

### 9.4 完整度（P0）

- 完整度只统计模板必填项中已确认且未过期的比例，另计来源覆盖和更新时间。
- 未知计入未完成，不计入已完成。
- 完整度影响排序，不替代硬性约束。约束不满足时，完整度再高也不进入结果。
- 卖家可以看到缺哪些字段，以及补齐后排序会如何变化的规则说明。不承诺具体名次。

验收：

- 两个商品都满足约束时，必填未知更少的商品排在前面。
- 卖家无法通过付费或填写营销文案提高完整度。

### 9.5 购买代理工具（P0）

对外提供工具接口，能力与常见商品目录协议对齐，便于以后接入 UCP 一类目录接口。首期至少包含：

| 工具 | 行为 |
| --- | --- |
| `search_products` | 按约束搜索。返回满足硬性约束的商品、价格、库存、两者的更新时间、可售状态、完整度、未知项摘要，以及未进入短名单的原因 |
| `get_product` | 返回已确认事实、信任等级、来源、未知项、冲突项、价格与库存更新时间、可售状态。不返回未确认候选。型号和 GTIN 未确认时为未知 |
| `compare_products` | 按同一组属性对比。空值和冲突显式标出 |
| `ask_seller` | 提交结构化问题：商品、属性、使用条件、已尝试的事实标识 |
| `create_handoff` | 生成卖家收银台链接，写入归因事件，并记下当时的价格和价格更新时间。请求必须带幂等键 |

要求：

- 工具返回结构化数据。代理不需要解析商品 HTML。
- 响应中的商品文案、规格和客服回答是数据，不作为给代理执行的指令。
- 搜索默认分页，单次返回规模设上限。
- 硬性结论包含约束名、状态和事实标识。状态为命中时必须有事实标识。未知和冲突不能写成命中。
- 约束因为未知或冲突无法判断、标价过期，或现货约束未满足时，商品不进入短名单，响应用稳定原因码说明。
- `GET /.well-known/ucp` 公布类目、工具和硬性筛选项，并写明付款发生在卖家收银台。
- 创建交接和回传订单必须带 `Idempotency-Key`。相同键和相同内容返回原结果。相同键但内容不同，返回 `idempotency_conflict`，且不执行第二次。失败响应不写入幂等缓存。

验收：

- 约束「输出功率不低于 65W，且持续功率」只命中条件匹配的已确认事实。条件不符的标称值不算命中。
- 手递链接打开后，卖家侧能看到平台带来的归因标识。

### 9.6 提问、去重与晋升（P0）

- 提问必须包含商品、属性和使用条件。缺字段的提问被拒绝，并提示缺什么。
- 相同商品、相同属性、相同条件并入同一问题簇。
- 问题簇已有晋升事实时，直接返回该事实，不通知卖家。
- 卖家助手只能引用已确认事实。事实不足时，问题进入人工问题箱，助手不得编造兼容性或参数。
- 人工回答保存为未确认问答。系统抽出候选事实，由卖家确认。
- 确认时若与已有规格冲突，进入冲突，不覆盖。
- 确认且无冲突，写成晋升事实，信任等级按第 7.2 节执行。
- 对提问按代理、买家和卖家设频率上限。超限返回已有事实或未知，不把请求堆给人工。

验收：

- 同一问题第二次调用 `ask_seller`，卖家问题箱不新增条目，接口返回已晋升事实。
- 助手在字段为未知时给出的肯定答复，不会自动变成可筛选规格。

### 9.7 卖家问题箱（P0）

- 按属性合并展示，而不是按聊天逐条展示。
- 卖家看到：问题、相关原文、候选事实、冲突提示。
- 卖家动作：确认候选、改值、标未知、标记冲突中的采用方。
- 回答一次对所有代理生效。

验收：

- 十个代理询问同一未知属性，问题箱只有一条待处理记录。

### 9.8 买家短名单页（P0）

- 展示候选商品、命中的约束、每条结论的来源、未知项和冲突项。
- 提供前往卖家收银台的动作，并带上归因标识。
- 买家可以用页面抽查代理结论，不把页面当作代理的数据接口。

验收：

- 短名单上不存在没有事实标识的硬性结论。
- 未知项在页面上可见，不被省略。

### 9.9 归因记录（P0 记录，P1 结算）

- `create_handoff` 记录买家、代理、商品、短名单、当时的价格、价格更新时间、时间和归因标识。读取归因不返回买家标识、代理标识、预算、地址或身份。
- 同一买家、同一商品在归因窗口内有多份交接时，以先创建的交接为准。后到的订单回传不记成另一笔平台成交，结账不被归因冲突拦住。
- 卖家回传订单号、金额、状态时，关联到未过期的归因标识。回传必须带幂等键。归因窗口时长上线前确认。
- 收银台展示交接时的价格。当前价格不同时标出差额。平台不保证成交价。
- P0 只保存关联，不扣款、不开发票。
- P1 按确认收货或售后期结束计算佣金，退货则冲正。

验收：

- 窗口外的订单不会记成平台成交。
- 一笔退货会把对应佣金标为待冲正。

### 9.10 买家席位（P1）

- 买家按席位使用采购代理和短名单历史。
- 未付费时可以保留体验额度。额度用尽后仍可查看已生成的短名单和证据。
- 卖家侧的目录读取不因买家额度而隐藏符合约束的商品。

### 9.11 卖家订阅（P1）

- 免费档限制在架 SKU 数和问题箱席位。
- 付费档提供更高 SKU 额度、多人问题箱、把已确认事实同步到卖家自己的店铺或目录接口。
- 订阅状态不改变搜索的硬性过滤规则。

### 9.12 授权购买（P2）

在 P0 的事实质量和归因数据被验证之后再做。

- 买家单独授权：最高金额、允许的类目和卖家、收货地址、是否必须可退、有效期。
- 只有同时满足授权和硬性约束的订单可以自动提交。
- 涨价、预售、定制品、不可退、事实冲突、必填未知，都退回给人确认。
- 高客单使用单独的一次委托，并提供冷静期内撤销。
- 每笔自动订单保存当时的约束、事实版本和授权标识。

验收：

- 授权金额之上的订单不会被提交。
- 事实在下单前变为冲突时，自动提交停止。

## 10. 隐私、安全与合规

- 买家的预算、地址、身份、联系方式可以出现在订单和授权里，不能写入公开商品事实或问题簇。
- 问题簇对外只保留商品、属性和使用条件。
- 商品描述、规格书文本、客服回答按不可信数据展示和存储，不进入代理的指令通道。
- 事实的确认、覆盖、冲突裁定和佣金冲正保留操作者与时间。
- 自动下单在 P2 必须能追溯到一个授权过的买家。平台首期不是支付机构，不保存完整支付凭证。
- 卖家对规格的真实性负责。平台保存来源和确认记录，用于退货和争议核对。

## 11. 非功能需求

| 项 | 要求 |
| --- | --- |
| 正确性 | 硬性筛选只使用已确认且未冲突的事实。未知不得被当成满足约束 |
| 可追溯 | 事实、提问晋升、归因、佣金冲正均可按标识回放 |
| 频率 | 提问接口有上限，避免把卖家客服当成实时查询通道 |
| 兼容 | 目录工具的字段尽量贴近既有商品目录协议，减少以后重复建设 |
| 可用性 | 抽取服务失败时，录入和查询仍可用，缺失处保持未知 |
| 范围 | 首期单品类、单区域结算币种。多品类和多币种不在 P0 |

性能数字在选定品类和预期并发后再定，不在本文写未经验证的指标。

## 13. 成功指标

上线后按真实卖家和真实提问计算。当前没有基线。

| 指标 | 定义 | 说明问题 |
| --- | --- | --- |
| 重复提问率 | 属性晋升后，同一问题簇再次通知卖家的比例 | 沉淀是否生效 |
| 未知字段率 | 在架商品必填属性仍为未知的比例 | 卖家确认是否发生 |
| 结论可核对率 | 短名单硬性结论中能打开事实来源的比例 | 代理是否在空字段上编造 |
| 选型用时 | 从提交需求到产生可执行短名单的时间 | 相对人工查手册是否下降 |
| 信息不符退货率 | 因参数、兼容或配件缺失导致的退货占归因订单的比例 | 晋升进规格的内容是否可靠 |
| 归因成交率 | 短名单产生可关联订单的比例 | 佣金模式是否成立 |

首期评审以重复提问率、未知字段率和结论可核对率为主。归因成交率用于决定何时开启 P1 结算。

## 14. 里程碑

| 阶段 | 交付 | 结束标准 |
| --- | --- | --- |
| P0 | 单品类模板、抽取确认、四个查询工具、提问晋升、短名单页、归因记录 | 同一问题第二次不再进入问题箱；短名单结论可打开来源 |
